    USDとは何か？

    USD（Universal Scene Description）は Pixarが開発した3Dシーン記述システムです。単なる「3Dファイル形式」ではなく、以下のすべてを一元管理するデータ構造＋ファイル形式＋ワークフローです。

    USD = 3Dワールド全体を管理するデータ構造 ＋ ファイル形式 ＋ Pipeline
    Geometry
    ジオメトリ（メッシュ）
    Material / Texture
    マテリアルとテクスチャ
    Light / Camera
    ライトとカメラ
    Animation / Rig
    アニメーションとリグ
    Physics
    物理属性
    Scene Graph
    シーン階層構造
    Reference
    参照関係
    Collaboration
    多人数協業
    💡USDが記述するのは「モデル1つ」ではなく、シーン全体です。

    従来ワークフローの課題

    FBXは「一括パッケージ」型で、zipアーカイブに近い構造です。1箇所変えるだけでファイル全体を再エクスポートしなければならず、チームではファイルの上書き事故が頻発します。

    特性FBXUSD
    部分更新❌ 全体を再エクスポート✅ 該当レイヤーのみ変更
    チーム協業❌ ファイルを上書き共有✅ レイヤー分担・非破壊
    大型シーン❌ すべてロード✅ Payloadで必要箇所のみ
    モデル再利用❌ コピー＆ペースト✅ Referenceで参照

    従来のパイプライン：

    モデリング（Maya）→ FBXエクスポート → アニメーション → FBXエクスポート → レンダラー → 再インポート

    結果として chair_final_final_new.fbx のようなファイルが氾濫し、誰が最新版かわからなくなります。

    映像制作でのUSD活用

    Pixar映画の1ショットにはキャラクター・建物・ライト・カメラ・煙・物理シミュレーションが混在します。USDは各部門が自分の担当レイヤーだけを管理し、最終的にComposeで合成するアプローチです。

    部門作業内容触らない領域
    Lightingライト調整キャラクターモデル
    Animation動作付けマテリアル
    Modelモデル修正カメラ

    USDの主な強み

    ① Layer（レイヤー分層）

    Scene ├── base.usd ├── lighting.usd ├── camera.usd ├── animation.usd └── physics.usd ↓ Compose 最終シーン

    lighting.usd を変更しても base.usd には触れません。各レイヤーが独立して管理できます。

    ② Reference（参照）

    モデルをコピーせず参照だけします。robot.usd を更新すると、参照するすべてのシーンに自動反映されます。

    ③ Non-destructive Override（非破壊上書き）

    元ファイルを変更せず、Layerで特定属性だけをオーバーライドします。例：ロボットの色だけ青に変えたい→元モデルを触らずに上位レイヤーで色だけ上書き。

    ④ Instancing（インスタンシング）

    工場内の1000脚の椅子を 1 Mesh + 1000 Instance で表現します。メモリとGPU効率が大幅に向上します。

    ⑤ 大規模シーンの遅延ロード（Payload）

    Payloadにより現在のカメラ周囲だけをロードします。都市・工場・病院など大規模シーンのロード時間を劇的に削減できます。

    課題と学習コスト

    USDは万能ではありません。初学者がつまずきやすい概念：

    Layer / Sublayer Reference Variant Payload Override Composition Arc

    また、DCC ソフト（Maya・Blender・Houdini・Unreal・Unity）のUSDプラグインの成熟度にばらつきがあり、クロスソフトのワークフローで互換問題が生じる場合があります。

    Isaac Simプロジェクトとの対応

    Isaac Sim + Robot + Warehouse + Navigation + Semantic + Physicsの構成はUSDのレイヤー管理と非常に相性が良いです：

    warehouse.usd │ ├── robot.usd ← ロボットモデルと関節 ├── shelf.usd ← 棚 ├── elevator.usd ← エレベーター ├── door.usd ← ドア（Variant: open / closed） ├── lighting.usd ← 照明 ├── materials.usd ← マテリアルライブラリ ├── physics.usd ← 衝突・質量・摩擦 ├── semantic.usd ← AI認識用セマンティックラベル └── sensors.usd ← LiDAR・カメラ

    door.usd を修正すると工場全体のすべてのシーンのドアが自動更新され、ロボットには一切影響しません。

    全体構造

    Stage ├── Prim（オブジェクト） │ ├── Attribute（データ） │ ├── Schema（能力） │ └── Time Samples（アニメーション） │ ├── Layer（レイヤー） │ ├── Composition（合成エンジン） │ ├── Opinions（衝突優先度） │ ├── Reference（参照） │ ├── Payload（遅延ロード） │ ├── Inherits（継承） │ └── Variant（多設定） │ ├── Instancing ├── LOD └── Hydra（レンダリング）
    Stage = すべてのPrim ＋ Compositionで処理された複数Layer = 完成したワールド

    Stage

    USDシーン全体のコンテナです。warehouse.usd を開くとStageを開いたことになり、ロボット・ドア・エレベーター・ライトすべてがここに属します。すべての操作は Stage → Prim → Attribute の流れで行います。

    📎 USD Glossary: Stage

    Prim（プリミティブ）

    USDではほぼすべてのオブジェクトがPrimです。Mesh・Camera・Light・Joint・Materialを問わずすべてPrimです。Primはパスで木構造に整理されます：

    /World
/World/Robot
/World/Robot/Arm
/World/Door
/World/Elevator

    📎 USD Glossary: Prim

    Attribute（アトリビュート）

    Primのデータフィールドです。位置・回転・色・質量などの具体的な値を保持します：

    def Xform "Robot" {
    double3 xformOp:translate = (1.0, 0.0, 0.0)
    float   mass               = 20.0
}

    📎 USD Glossary: Attribute

    Time Samples（タイムサンプル）

    各時刻のAttributeの値で、アニメーションを構成します。ロボットの移動軌跡・アームの動き・カメラパスはすべてTime Samplesで実現されます：

    double3 xformOp:translate.timeSamples = {
    0: (0, 0, 0),
    1: (1, 0, 0),
    2: (2, 0, 0),
}

    Schema（スキーマ）

    Primに「何ができるか」を定義します。2種類あります：

    種類役割特性
    IsA SchemaPrimのタイプを決定（Mesh・Camera・Lightなど）1 Primに1つのみ
    API SchemaPrimに追加能力を付与（Physics・Collisionなど）複数重ねて適用可能

    Isaac Simでの例：

    Cube + RigidBodyAPI + CollisionAPI  →  落下・衝突する物理ブロック

    主なPhysics API Schema：

    RigidBodyAPI CollisionAPI PhysicsDriveAPI PhysicsJointAPI

    📎 USD Glossary: Schema ｜ Isaac Sim Physics Schema

    Layer（レイヤー）

    データレイヤーであり、各 .usd ファイルが1つのLayerです。役割ごとにLayerを分割し、互いに干渉しないようにします：

    structure.usd ← 壁・床・天井（静的・ほぼ変更なし） robot.usd ← ロボット lighting.usd ← 照明 physics.usd ← 物理属性オーバーライド

    📎 USD Glossary: Layer

    Composition & Opinions

    Composition はUSDのコアエンジンで、複数のLayerを最終シーンへ合成します。Opinions は複数のLayerが同じAttributeを変更する際の優先順位ルールです。

    Composition Arc（合成弧）の優先順位（高 → 低）：

    1
    Local最高優先度
    2
    Reference
    3
    Payload
    4
    Inherits
    5
    Variant
    6
    Sublayer最低優先度

    📎 Composition Arcs詳解 ｜ USD Glossary: Composition

    Variant（バリアント）

    同一Primに複数の設定セットを持たせ、1クリックで切り替えられます。複数のモデルファイルは不要です：

    Door
├── VariantSet: state
│     ├── open
│     └── closed

Robot
├── VariantSet: sensor_config
│     ├── lidar_only
│     ├── camera_only
│     └── dual_sensor

    応用例：病院シーンの「昼 / 夜 / 雨 / 停電」をVariantで切り替え。

    📎 USD Glossary: VariantSet

    Reference（リファレンス）

    別のUSDファイルを参照します。データをコピーしないため、robot.usd を更新すると参照するすべてのシーンが自動更新されます：

    def Xform "Robot" (
    references = @./robot.usd@
) {}

    📎 USD Glossary: Reference

    Payload（ペイロード）

    Referenceの上位版で、必要な時だけロードします。大型シーンに最適です：

    Hospital
├── Wing_A.usd  ← Payload（現在ロード中）
├── Wing_B.usd  ← Payload（未ロード）
└── Wing_C.usd  ← Payload（未ロード）

    📎 USD Glossary: Payload

    Inherits（インヘリッツ）

    複数のPrimが同じ属性セットを共有します。親Primを変更すると継承しているすべてのPrimが自動更新されます。OOPのclass継承に相当します。

    活用例：すべての机が同じ木目マテリアルを継承 → 1箇所変更で全机に反映。

    📎 USD Glossary: Inherits

    Instancing（インスタンシング）

    1つのMeshをシーン内で何度も再利用します。GPUには1つ分のデータしか保存されません。

    1000個の棚 = 1 Mesh ＋ 1000 Instance → メモリとレンダリングコストを大幅削減。

    📎 USD Glossary: Instancing

    LOD（Level of Detail）

    カメラからの距離に応じてモデルの精度を自動切り替えします。遠距離では低ポリゴン、近距離では高ポリゴンを使用します。大型工場や屋外シーンで大幅なパフォーマンス向上が期待できます。

    Hydra（ハイドラ）

    USDのレンダリングフレームワークです。USDがシーンを記述し、Hydraがそれを表示します。レンダラーをいつでも交換可能（RTX・Storm・Arnold・RenderMan…）。

    学習優先度（Isaac Sim研究方向）

    優先度概念理由
    ⭐⭐⭐⭐⭐Prim + AttributeUSDワールドのあらゆるオブジェクトとデータの基礎
    ⭐⭐⭐⭐⭐Schema（特にAPI Schema）物体が衝突・質量・関節・センサー能力を持つ理由を理解
    ⭐⭐⭐⭐⭐Layer + CompositionUSDの最核心設計思想・多人数協業とシーン構成の基礎
    ⭐⭐⭐⭐Reference + Payload再利用・拡張可能な大規模デジタルツインシーンの構築
    ⭐⭐⭐⭐Variant + Instancingシーン設定の即切り替えと大量重複アセットの効率管理

    目標

    研究室・廊下・エレベーターを現実に十分近いUSDシーンとして構築し、Isaac Simでのロボットナビゲーション・シミュレーションに活用する。

    ① ジオメトリ構造

    最も基礎的な部分で、シーンの物理的骨格を決定します。

    要素注目点
    床・壁・天井寸法精度（誤差 ±2cm 以内を推奨）
    ドア幅・開閉方向・自動ドアか・回転軸の位置
    廊下有効幅（ロボットの通過可否に直結）・コーナー半径
    エレベーターかご内寸法・ドア幅・階高・停止階数
    障害物固定家具（机・椅子・棚）の位置と外形
    💡ロボットナビゲーションが気にするのは外観の細部ではなく、通行可能空間の形状です。ジオメトリ精度がナビゲーション結果に直接影響します。

    ② 物理属性（Physics Schema）

    シミュレーション内でロボットとシーンが正しくインタラクションするために必要です。

    要素パラメータ
    床の摩擦係数車輪型ロボットのスリップ度（タイル ≠ カーペット）
    コライダー（Collider）各物体に簡略化コリジョンメッシュが必要（レンダリングメッシュそのままはNG）
    ドアのヒンジ関節回転軸位置・開閉角度制限・スプリング復帰の有無
    エレベーターの動作垂直変位・加速度・ドア開閉タイムライン
    床の平坦度スロープの有無・敷居の高さ（車輪の乗り越えに影響）

    ③ センサー環境（Sensor-ready）

    ロボットはセンサーで世界を認識するため、シーンはセンサーに対しても「リアル」である必要があります：

    センサーシーンへの要件
    LiDAR壁・ドア・柱のジオメトリ精度；ガラスは特殊マテリアル処理が必要
    RGBカメラテクスチャ（床柄・壁色・サイン）・照明条件
    深度カメラマテリアルの反射率（鏡面反射で深度情報が失われる）
    IMU床の傾斜・振動（主にIsaac Simレイヤーで処理）

    ④ セマンティックラベル

    AI認識トレーニング（セグメンテーション・物体検出）に使用します。

    • 各クラスにセマンティックラベルを設定：door・wall・elevator・person
    • エレベーターボタン・ドアノブなどの細部を個別ラベル付けするかはタスク次第

    ⑤ USDレイヤー設計

    適切なレイヤー設計によりシーンの保守性・拡張性が大幅に向上します：

    building.usd ├── structure.usd ← 壁・床・天井（静的・ほぼ変更なし） ├── furniture.usd ← 机・椅子・棚（静的障害物） ├── doors.usd ← 全ドア（Variant: open / closed） ├── elevator.usd ← エレベーター（アニメーション・物理） ├── lighting.usd ← 照明配置 ├── materials.usd ← マテリアルライブラリ ├── physics.usd ← 物理属性オーバーライドレイヤー └── semantic.usd ← セマンティックラベルオーバーライドレイヤー
    💡ドアの開閉状態とエレベーターの現在階は VariantSet として設計すると、シーン設定をワンクリックで切り替えられます。

    テスト項目

    ① ジオメトリ検証

    • usdviewでシーンを開き、スケールが現実と一致するか目視確認
    • ロボットを配置後、床に正しく立っている（貫通なし・浮きなし）
    • 廊下の有効幅がロボット通過に十分か（≥ 0.5m のマージン推奨）

    ② 物理シミュレーション

    • ロボットが床を走行してもスリップ・振動が起きない
    • ドアをロボットが押せる、またはプログラムで開閉制御できる
    • エレベータードア開閉タイムラインが正確で、かごの上下移動に貫通なし
    • ロボットのエレベーター乗降時にドア枠・敷居との衝突なし

    ③ ナビゲーション

    • NavMeshを生成し、廊下・研究室・エレベーター内部がすべてナビ可能と確認
    • 研究室 → 廊下 → エレベーターの完全なパスプランニングが成功する
    • ドア閉時にナビゲーションが通行不可と正しくマークされる

    ④ センサー

    • 廊下でのLiDAR点群の形状が正確（壁面が平行、ドア開口部が明確）
    • カメラ映像と現実の写真を比較（色・照明がおおよそ一致）
    • ガラス・鏡面エリアでLiDARに特殊マテリアル設定が必要かを確認

    ⑤ パフォーマンス

    • シーン全体のロード時間 < 10秒（超える場合はPayloadによる分割を検討）
    • ロボット動作中の物理ステップが安定（目標 ≥ 60Hz）

    推奨構築順序

    各ステップ完了後に個別保存してテストしてください。すべて完成してからまとめてテストするのは避けましょう。

    ① データ収集計測 ＋ 写真撮影 ＋ 平面図
    ② 構造レイヤーのモデリング（structure.usd）床・壁・天井
    ③ 物理属性の追加（physics.usd）まずロボットが床に立てるか確認
    ④ ドアとエレベーターの追加doors.usd + elevator.usd（アニメーション・関節含む）
    ⑤ 家具・障害物の追加（furniture.usd）
    ⑥ マテリアルと照明の追加materials.usd + lighting.usd
    ⑦ セマンティックラベルの追加（semantic.usd）
    ⑧ 全フローのテスト（テスト項目①〜⑤）
